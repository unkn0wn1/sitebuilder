# 0001: Nuxt as the framework

- **Status:** Accepted
- **Date:** 2026-11-16

## Context

We need one stack for the builder UI, the block components, the API and the static site output. The main options were Nuxt (Vue), Next.js with Puck (React), and Astro. There is no mature Vue equivalent of Puck, but Vue 3, Vite, TypeScript and Tailwind is the stack the project lead knows and prefers.

## Decision

Use **Nuxt** (Vue 3, Vite, TypeScript) for the builder app, the Nitro API and static generation. Tailwind CSS for styling, with Flowbite / flowbite-vue planned for the builder UI.

## Consequences

- One language and component model across editor, blocks and published output, so the preview is exactly what ships.
- Nitro gives us the API in the same project, with no separate backend framework.
- `nuxt generate` gives static output out of the box.
- We cannot use Puck directly (React). We borrow its JSON block shape instead and build our own Vue editor, or adopt a Vue one if it matures.
- Astro remains a fallback renderer for published pages if Nuxt output ever proves heavier than needed, since it can render Vue components.
